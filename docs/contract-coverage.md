# Contract Test Coverage

Issue #240. The contracts have extensive Rust tests, but until now their coverage was never measured. This page describes how coverage is now measured, reported on PRs and prevented from decreasing.

| Piece | Location |
|---|---|
| Workflow | [`.github/workflows/contract-coverage.yml`](../.github/workflows/contract-coverage.yml) |
| Ratchet / report script | [`scripts/coverage-ratchet.mjs`](../scripts/coverage-ratchet.mjs) |
| Exclusions (with justifications) | [`contracts/coverage/exclusions.txt`](../contracts/coverage/exclusions.txt) |
| Committed baseline (fallback) | [`contracts/coverage/baseline.json`](../contracts/coverage/baseline.json) |

## What runs

We measure coverage with [`cargo-llvm-cov`](https://github.com/taiki-e/cargo-llvm-cov), which uses LLVM source-based instrumentation (`-C instrument-coverage`). We chose it over grcov because it reports region coverage as well as line coverage. That lets it catch error branches that are only partly hit, such as the unhappy side of an `assert!`.

On every PR that touches `contracts/**`, the workflow does the following:

1. Runs `cargo llvm-cov --workspace --locked --no-report`, which runs the same test suite as the Contracts Required Gate.
2. Writes three reports, all filtered by `exclusions.txt`:
   - `coverage-summary.json`: the ratchet input.
   - `coverage-html/`: uploaded as the **`contract-coverage-html`** artifact and kept for 30 days. Download it, open `index.html` and drill into any file. Uncovered lines and regions are highlighted.
   - `lcov.info`: for editor gutters (for example the VS Code "Coverage Gutters" extension).
3. Posts or updates a **sticky PR comment** with:
   - total line, function and region coverage for this PR, the baseline and the difference
   - a per-file table for every `.rs` file the PR changed
   - a link to the HTML artifact
4. Enforces the **ratchet** (see the next section).

On every push to `main`, the same job runs and uploads `contract-coverage-summary`. Later PRs use that artifact as their baseline.

## Ratchet (no decrease), not an absolute bar

- A PR fails if line, function or region coverage drops by more than **0.05 percentage points** compared with the latest `main` run. The 0.05 allowance absorbs rounding noise.
- There is deliberately **no minimum percentage**. Coverage can only go up, so it improves over time without blocking unrelated work.
- If no `main` artifact exists yet, the job uses `contracts/coverage/baseline.json` instead. If that file's values are still `null`, the job only reports and does not block.

### Waivers

If a coverage decrease is intended, for example because you deleted well-tested dead code or moved code into an excluded generated file, apply the **`coverage-waiver`** label to the PR and explain why in the PR description. Adding or removing the label triggers the job again. Reviewers should treat an unexplained waiver as a blocking comment.

## Exclusions

Only the following paths are excluded. The same justifications appear as comments in `exclusions.txt`:

| Pattern | Why |
|---|---|
| `/tests/`, `/src/tests/` | This is test code. Counting it would raise the percentage without saying anything about production paths. |
| `/src/test_fixture.rs` | Fixture helpers used only by tests. They are never part of the deployed WASM. |
| `/src/generated/` | Code generated by `scripts/codegen-events.mjs`. The Event Schema Drift Gate already checks it byte for byte. |
| `/.cargo/registry/`, `/.cargo/git/`, `/rustc/` | Third-party and standard-library code. |

When you add an exclusion, you must add a justification comment in the same PR.

The first `main` run after this workflow merges establishes the baseline. To record it in the repo, which also makes the fallback ratchet start blocking, run the following commands:

```bash
cd contracts
cargo llvm-cov --workspace --locked --no-report
cargo llvm-cov report --json --summary-only \
  --ignore-filename-regex "$(grep -vE '^\s*(#|$)' coverage/exclusions.txt | paste -sd '|' -)" \
  --output-path ../coverage-summary.json
cd ..
node scripts/coverage-ratchet.mjs --summary coverage-summary.json \
  --write-baseline contracts/coverage/baseline.json
```

After running them, update the table above.

## Running locally

```bash
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov --locked
cd contracts && cargo llvm-cov --workspace --open   # builds and opens the HTML report
```
